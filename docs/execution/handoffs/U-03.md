## Delivered scope

The review package provides normalized presentation types, an HTTP reader over
the frozen generated UI client, and a bounded server-rendered handler for
`/reviews` and `/reviews/{id}`. Generated DTOs remain private to the adapter;
the handler consumes only package-local types. It validates the requested
identity against every detail response, rejects malformed or oversized pages,
plans, action unions, manifests and draft query fields, and sanitizes transport,
protocol and context errors. Redirects are not followed and response bodies are
bounded. Pages are escaped and carry `no-store`, `no-cache`, `noindex` and
`nosniff` headers.

Review pages show the immutable plan revision and digest, optional source,
configuration, mapping, manifest and desired-state fences, preconditions,
capabilities, conflicts, blocking issues, exact manifest entries and action
file/episode/subtitle scope. Unknown fences and observations stay visibly
unknown. Arr registration and exact import are rendered as separate phases;
registration approval is never presented as import approval. Standalone action
plans remain distinguishable. Monitoring is unchecked unless the immutable plan
explicitly records opt-in, and hardlink failure is described as a separate copy
plan. Client, torrent and irreversible impacts are shown as explicit scope.
Only GET/HEAD draft forms are emitted; approval, retry and mutation dispatch
remain API-owned.

The workflow package provides normalized workflow, step, effect and
cancellation types, the same bounded generated-client boundary, and handlers
for `/workflows` and `/workflows/{id}`. The HTTP reader joins each linked
action-run observation to its step while keeping effect state, outcome,
unresolved IDs, last observation, retry timing, errors and cancellation visible.
Ordered steps render registration/import gates, standalone versus composed
recipes, queued/running/succeeded/failed/blocked/reconciling/cancelled/
deadline-exceeded/already-satisfied states, destructive impacts, and the rule
that cancellation prevents later dispatch while late or partial effects remain
available for reconciliation. Draft forms preserve deep-link IDs, immutable
binding fields, idempotency keys and operator notes across read-only reloads.

No UI package imports root internals, database/storage/upstream packages,
filesystem mounts, credentials or media paths. No approval, retry, cancellation
or upstream/filesystem mutation is called by this lane. Fixtures use synthetic
`httptest` servers and in-memory readers only.
