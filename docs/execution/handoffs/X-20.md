## Product result

Product commit: `c20315353bab7e0545204d21a5fd9e1362964b49` (`feat(arr): migrate
write adapter reads to standalone clients`).

The root Arr write adapter now constructs exactly one selected standalone
client for each configured connection. Sonarr reads use the public
`ListSeries`, `GetSeries` and `ListEpisodesWithFiles` methods. Radarr reads use
`ListMovies` and `GetMovie`. The adapter translates normalized public client
observations into its private `nativeTitle`, `nativeEpisode` and `nativeFile`
models before applying the existing root registration, import, path-mapping,
identity and read-back rules. No generated DTO or generated package escapes the
client module boundary.

The adapter translates the standalone typed error vocabulary into sanitized
`domain.UpstreamError` values while retaining status and retryability. The
adapter preserves caller cancellation and deadline identity, including custom
transport and response-body failures, through an internal context-error
tracker; private endpoint, credential and transport text is never returned.

Standalone page completeness and empty continuation checks are required before
the adapter accepts catalog or episode observations. Sonarr episode conversion
retains the standalone module's strict episode, nested file, series identity,
file identity, duplicate identity and complete-coverage validation. Radarr
movie conversion retains strict movie and nested movie-file identity checks.
Provider-ID maps are copied into the private root model so a valid native
provider alias remains usable by registration matching.

The existing registration payload needs fields intentionally omitted from the
standalone read-only public models: `rootFolderPath`, `qualityProfileId`, and
Sonarr season metadata. After the typed catalog read, the adapter performs one
bounded, strict, private metadata read against the same catalog endpoint and
requires an exact ID-set match before merging only those registration fields.
The existing title read-back path similarly performs the typed title read first,
then an exact ID-bound metadata read. A metadata snapshot change, duplicate,
missing identity or contradictory monitored value fails closed. This bridge
does not expose raw upstream data or generated types and does not replace the
standalone identity/error validation.

History remains on the root adapter's private transport because the published
Sonarr and Radarr modules do not expose history in their frozen read contracts.
Synthetic command payload construction and command read-back remain root-owned
for the same reason. The public constructor still reports the independent
registration and import mutation capabilities as unknown while G-01 is open;
no native registration, manual-import command, search or other mutation was
enabled. The unexported synthetic constructor remains the only test seam for
the existing reviewed command/reconciliation behavior.

Synthetic Arr write fixtures now include the required native title path,
monitored, episode numbering, `hasFile`, and nested file identity fields. The
fixture suite continues to cover exact preview binding, no-search registration,
explicit monitoring, already-satisfied idempotency, lost command response,
history/file read-back, partial association evidence, subtitle validation,
foreign and contradictory file identity, multi-episode files, strict
duplicate-key/UTF-8 handling and sanitized errors. Additional migration tests
prove that a legacy title missing the standalone path requirement does not fall
back to the old permissive decoder and that typed unauthorized responses map to
a sanitized root error without response-body leakage.

No live Arr service, credential, private endpoint, tracker data, media
inventory, filesystem mutation or upstream write was used.

## Integration and blockers

The public Sonarr and Radarr pseudo-version is consumable with `GOWORK=off`
and no local `replace` directive. There is no module bootstrap blocker for
this lane. The standalone modules remain independently versioned and own
their generated code, transport/authentication, bounds, strict decoding and
typed upstream errors.

G-01 remains an explicit product blocker. The adapter therefore keeps both
native mutation capabilities unknown and never dispatches production
registration or manual-import writes. Existing synthetic capability injection
is unexported and covered only to preserve the reviewed read-before-write,
preview-binding, command read-back, lost-response and no-retry evidence.
