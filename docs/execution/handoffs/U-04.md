## Delivered behavior

`ui/internal/trash/` adds an HTTP-only generated-client reader and normalized
trash models for list/detail reads. It preserves opaque entry IDs, exact
`rootId` plus `relativePath` original targets, selected manifest identity,
role, type, digest, observed time and size, expiry, lifecycle state,
capabilities, client associations and holds. Optional normalized fields keep
per-effect stop/remove evidence, restore conflicts, per-item outcomes,
unresolved effects and late effects explicit; when the frozen response does
not provide those fields, the renderer says `unknown` instead of inferring a
success or absence. The list and detail readers reject redirects, oversized or
invalid UTF-8/JSON bodies, duplicate or unknown members, missing required
fields, invalid paths, duplicate page identities and detail identity mismatch.

The trash detail view renders an explicit two-step GET-only restore/purge draft
flow with idempotency, operator, reason and If-Match context. It states that
the API owns mutations and exposes no permanent-delete shortcut outside the
trash flow. POST, PATCH, DELETE and other methods are rejected before the
reader is called. Responses are private, no-store, noindex and nosniff, and
all dynamic HTML is escaped.

`ui/internal/settings/` adds normalized HTTP readers and views for
configuration, connections, connection checks, storage roots and path
mappings. It preserves source (`yaml` or `api`), editability, document and
revision metadata, startup time, restart-required reload policy, restart
required state, health/version/capabilities, credential state, retired
timestamps, storage permissions/watch settings, and path mapping connection
and root context. Configuration ETags are retained and individual API-owned
resource ETags are retained when returned, so GET drafts can carry If-Match
and idempotency/operator context. YAML/file-owned records render read-only
instructions. Credentials, writeOnly fields, key paths and raw sanitized
upstream errors are never rendered; endpoint userinfo and query credentials
are removed before normalization, and path-shaped source document IDs are
reduced to `configured document`.

Both readers use bounded transports and per-request context deadlines. Strict
decoding rejects duplicate keys, unknown fields, trailing JSON, invalid UTF-8,
missing/null required evidence and excessive nesting. List/page coverage,
enum values, config identities, timestamps, path targets, duplicate resource
IDs and request/response identity bindings are validated before rendering.

## Acceptance contributions and limitations

The product-path portions of A-25, A-26, A-27 and A-30 are represented by
trash retention expiry, held/ready/restoring/purging/purged/blocked states,
manifest and client evidence, conflict/effect sections, and the two-step
read-only UI boundary. A-38, A-39 and A-42 are represented by source
provenance, YAML/API editability, revisions, restart metadata, ETag draft
context, retired records, duplicate-ID rejection, credential-state-only
rendering and redacted check errors. A-57 is represented by explicit holds,
blocked state, expiry and unknown unresolved/late effect sections.

The frozen `TrashEntry` schema currently exposes expiry, manifest, original
targets, capabilities, associations and holds but no created-at/retention
policy, per-file outcome, restore-conflict or stop/remove-effect members. The
UI therefore keeps these dimensions visible as unknown or optional evidence;
it does not fabricate default/custom retention or effect success. Browser
router composition, asset navigation and API mutation endpoints remain
outside this lane and need coordinator integration/review.
