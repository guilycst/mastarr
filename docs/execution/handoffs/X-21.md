## Contract and work

The read adapter now constructs the public `github.com/guilycst/mastarr/clients/jellyfin`
client at the pinned root-module pseudo-version. All Jellyfin HTTP requests,
token authentication, redirect refusal, request deadlines, response bounds,
strict UTF-8/JSON decoding, pagination metadata validation and typed upstream
errors remain inside that standalone module. The root adapter owns only
Mastarr configuration validation, signed local cursors, bounded snapshot
aggregation, path mapping and translation into root domain/port observations.

`Version`, `Libraries`, `ObserveItem` and per-library item traversal translate
the standalone system, library, item, provider relationship and media-source
observations. Provider namespaces and relationships remain preserved, while
path-only item evidence stays distinct from native playable media evidence and
configured mapping ambiguity/unavailability remains explicit. Native malformed
identity evidence is surfaced as a sanitized unknown result; it is never
converted into a complete absence claim.

The existing write adapter was already migrated to the same standalone client
by the approved X-09 lane and remains unchanged here. Its version-bound library
refresh gate, unsupported item scope, accepted-refresh evidence and later
availability separation were revalidated. No read path calls a mutation and no
generated DTO or direct upstream request helper crosses into the root package.

The synthetic Jellyfin fixture used by the read adapter is now owned at
`tests/fixtures/jellyfin/read.json`. It covers system information, library
folders, paginated movie/series items, provider IDs, mapped media sources,
path-only observations and malformed/unsupported source variants. Fixture
handlers accept only the synthetic token and assert read operations remain
GET-only. The fallback test uses the standalone client's canonical `/UserViews`
route with a scoped `userId` query.

The product change is committed at
`d54f9b5937f5dc42829b3f56ee1e392a61bccf8a`:

- `internal/adapters/jellyfin/read/client.go` delegates upstream operations

  routes, translation, strict malformed evidence and path/coverage behavior.
- `tests/fixtures/jellyfin/read.json` is the module-scoped synthetic fixture.
