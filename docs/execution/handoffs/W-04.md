## Behavior

`internal/reviews` is the durable review boundary. It stores immutable plan
revisions and exact desired-state bytes, validates plan/revision/digest/source
and configuration fences, enforces action-specific approval kinds, and commits
the review decision, optional action run and idempotency record in one SQLite
transaction. Registration approval cannot be reused for an import plan. Same
keys replay the same resource; changed payloads conflict. Invalid, stale,
expired, forged, blanket and oversized requests fail before any action run.

`internal/workflows` stores a bounded ordered recipe over those plans. Every
step retains its exact plan binding, approval gate, decision/action links and
effect projection. Creation validates and rechecks all plan revisions inside a
transaction. Step approval requires the current step and completed prior
steps, then delegates the exact binding to `reviews.Service`. Sync projects
durable action state and effect evidence into step and workflow views. Cancel
and deadline handling persist closure, request cooperative cancellation for
linked action runs, cancel pending steps and reject later approvals or appends.
Appending a step updates the stored recipe and has replayable idempotency.

The lane deliberately uses ordered recipes rather than a generic DAG or an
outbox. Filesystem capability limits remain fail-closed, Arr native writes
remain disabled by G-01, and Seerr remains read-only.

  workflow approval blocks the later import until registration succeeds.
- A-15: immutable plan/revision/digest and exact source/config/mapping/manifest
  bindings are rechecked; stale, forged, expired and changed intent is rejected.
- A-32: review decision, queued action and idempotency record share one local
  SQLite transaction; concurrent and replay requests do not duplicate work.
- A-35: cancel/deadline closes the workflow, marks linked actions for
  cooperative cancellation and prevents later dispatch while preserving late
  action evidence.
- A-37: workflow state and step/effect evidence are durable and can be read
  after the caller/BFF leaves; failed, blocked, reconciling and cancelled
  states remain distinct.
- A-56: bounded IDs, actor/reason fields, recipe size, plan input and required
  preconditions reject malformed or oversized requests before writes.
