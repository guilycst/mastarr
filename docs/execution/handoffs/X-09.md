## Contract and work

The adapter implements `ports.MediaServerRefreshPort` and `ports.CapabilityPort`.
It translates the public `clients/jellyfin` refresh result and typed errors into
Mastarr port/domain values. No generated DTO crosses the adapter boundary.

Library refresh is the only enabled mutation scope. A successful native 200, 202,
or 204 is returned as `RefreshResult.Accepted` with operation and acceptance
 evidence. The result deliberately has no availability claim; later Jellyfin
inventory reads remain separate observations. Item refresh validates the explicit
item ID, then returns `OutcomeUnsupported` before any native request because the
standalone compatibility fixture has no positive, version-pinned item-scope
acceptance. Wrong connection, unknown scope, a library item ID, nil context and
malformed item IDs fail before dispatch.

Upstream statuses are mapped into the root sanitized vocabulary. Cancellation and
deadline identity is preserved with `errors.Is`; upstream URL, token, response
body and transport text do not escape. Capabilities are independent per scope:
`jellyfin.refresh.library` is supported by the compatibility contract and
`jellyfin.refresh.item` is unsupported pending positive evidence.
