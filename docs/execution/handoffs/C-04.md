## Product slice

Product commit `9f1607a5ff4ea901249a8d50f90848d35035a064` adds a strict generated
HTTP boundary and the process bootstrap seam.

The transport server wraps the generated `net/http` handler and applies one
policy layer for request IDs, bounded bodies, invalid UTF-8, duplicate/unknown
JSON fields, nested depth, manifest byte/entry limits, origin and conservative
CSRF/CORS checks. Mutation routes enforce validated idempotency keys and the
documented ETag/If-Match preconditions. Responses use sanitized
`application/problem+json`; context cancellation/deadline identity is retained
through `errors.Is` without exposing URLs, bodies or transport details. Health
and readiness are separate, with readiness returning 503 until bootstrap has
completed.

The assembled configuration routes translate the existing configuration
service into generated API DTOs. List responses carry bounded observations and
do not claim complete cursor coverage when a durable cursor service is not
available. The other documented route families deliberately return a typed,
sanitized 503 until their application services are wired; they never fabricate
an authoritative empty result.

`cmd/mastarr` validates environment input with the repository bootstrap
contract, creates the 0700 data directory, opens the listener before startup
work, opens SQLite/migrations, obtains the credential encryption key, loads
persisted API configuration, verifies encrypted credential envelopes, and only
then publishes readiness. With no supplied key it uses the persistent key path
owned by the credential service (`<data-dir>/keys/credentials.key`); explicit
environment and secret-file sources remain supported. Startup errors are
sanitized, do not log secrets or private paths, and preserve typed `errors.Is`
identity. SIGINT/SIGTERM drives bounded graceful HTTP shutdown and dependency
closure.

## Deliberate boundaries and blockers

- Configuration mutations currently update the in-process configuration
  manager. The manager has no persistence callback in this owned slice, so a
  restart restores only rows already present in SQLite. A later storage
  integration must bind successful create/patch/retire operations to one
  durable transaction before claiming restart persistence.
- Cursor-bearing list requests fail closed with `snapshot_expired` until the
  durable snapshot/cursor service is assembled.
- Action, discovery, download, media, descriptor, trash, review, scan and
  workflow routes remain explicit `service_unavailable` responses until their
  application services are injected. This preserves unknown state and avoids
  false success.
- Idempotency records in this transport slice are process-local and bounded;
  durable action-run/idempotency integration remains owned by execution and
  storage lanes.
- v0.0.1 intentionally has no application authentication. Actor attribution
  remains unauthenticated; origin policy supplies request-boundary CSRF/CORS
  protection only.

The existing G-01 Arr native registration/import block, F-05 filesystem
capability block, Seerr read-only policy and qBittorrent safety policy remain
unchanged. No live writes were enabled.
