## Contract and work

- Linked specification sections and relevant invariants: `docs/specs/spec-001-media-reconciliation/data-and-recovery.md` descriptor persistence/retention and filesystem safety sections; `docs/specs/spec-001-media-reconciliation/http-api.md` descriptor metadata/content and exact deletion sections; I-13 private-data boundary.
- Intended result and capability limits: retain one exact descriptor per local download and descriptor type, with bounded content, SHA-256 digest, capture source/time, honest unavailable state, private root-confined storage, and independently reviewed exact deletion. This is a service seam; HTTP and download-adapter wiring remain downstream C-04/W-03 work.
- Changes completed / remaining:
  - `CaptureExport` accepts only a source marked as an export with nonempty source identity, verification reference, expected digest, and bounded bytes. The service recalculates the digest and never trusts caller bytes without that evidence.
  - `CaptureMounted` reads only a configured root-relative regular file. Unix builds resolve every component with no-follow descriptor-relative opens; traversal, symlinks, special files, root targets, and path escapes fail closed. The opened file identity, size, and digest are checked across two bounded reads.
  - Private storage is created with a `0700` root/object directory and `0600` descriptor objects. Publication uses an exclusive staged object and no-replace hardlink, with size, mode, object identity, and parent-sync checks.
  - `Get`/ordinary `Record` responses contain metadata only. Availability and size are reported only after private content read-back matches the retained digest; missing or changed content is exposed as unavailable metadata. `Content`/`ContentBytes` are explicit byte-retrieval calls.
  - `RecordUnavailable` persists a bounded reason without inventing a digest and never downgrades an available descriptor. Repeated capture/unavailable operations are keyed by download/type and are idempotent.
  - `Delete` requires an exact descriptor UUID and explicit irreversible acknowledgement. It verifies the selected object, rejects replacement or content drift, removes only that object, syncs its directory, and marks metadata deleted in a transaction with one redacted `audit_events` row. Repeated deletion returns retained audit/provenance metadata without another filesystem effect. Unsupported platforms fail closed for physical deletion.
