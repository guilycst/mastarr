## Contract and work

The adapter implements the existing `ports.MediaManagerWritePort` and
`ports.CapabilityPort` contracts for one scoped Radarr or Sonarr instance. It
keeps registration and manual import as separate operations with independent
capability evidence. `Register` validates the provider and explicit fields,
reads the catalog before considering a mutation, returns `already_satisfied`
when the requested state already matches, preserves omitted existing fields,
and builds a new title with `monitored=false` and explicit no-search options.
Every synthetic mutation is followed by title identity and field read-back.

`Import` requires a non-empty preview revision, exact source-relative targets,
explicit movie/episode associations and a supported `copy` or `move` transfer.
Subtitle roles are checked against the source extension before any request.
Sonarr files sharing one source are grouped while preserving every episode
association. The operation observes current files and import history before a
command, skips an already materialized association set, and reads episodes or
movie files plus history again after dispatch. A lost command response is
resolved only by exact file read-back; partial associations remain
`outcome_unknown` with no success effect and no blind retry.

The public `New` constructor always installs independent unknown gates for
`arr.registration` and `arr.manual-import`. Consequently production callers
cannot dispatch native Arr writes while G-01 is open. The unexported test-only
constructor accepts synthetic capability evidence solely to exercise payload,
read-back and lost-response protocol models. No live service, credential,
private coordinate, or real media inventory was used. Generated standalone
client migration remains X-20 work.
